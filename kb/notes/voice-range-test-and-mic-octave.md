# Singing voices: profiles, Find my range, the mic's octave rule

## Context
Touching the voice profiles (`instruments/voice-*.json`), `Instrument::voice`, mic grading in `practiceUpdate()` (`src/gui_practice.cpp`), `heardCents()`/`judgeNote()`/`sameHeard()`/`micSearch()`/`sungNote()`/`myVoice()` in `src/sound.cpp`, `Audio::micSamples()`, or the Find my range window (`rangeWindow()`, `noteStaff()` in `src/gui_settings.cpp`) (#87).

## Rule
A voice is an ordinary profile with `"voice": true` (soprano, alto, tenor and bass presets; tenor and bass have `octave: -1` like the guitar, and the sheet stays in treble clef). Code asks `in.voice`, never the id: `my-voice` and agent-defined voices (`define_instrument` takes `voice`) carry the flag. The mic always goes through `judgeNote(heard, want, tolerance, myInstrument)`: for a voice `heardCents()` folds the distance to the nearest octave of the note, so an octave off is Right and never Octave (orange). The "(octave too high/low)" readout is hidden for voices. Folding alone isn't enough: the mic must also *hear* the octave, so play-along's pitch search and window come from `micSearch(myInstrument, rate)`, which widens a voice's search an octave each way (and its window to two periods of the new fmin, 4096 for the bass) while other instruments keep the old range and 2048. Wait for me asks for a new attack between notes `sameHeard()` can't tell apart (a repeat; for a voice also an octave leap). Find my range records one gated YIN pitch per new batch of mic samples over `VOICE_MIN_HZ..VOICE_MAX_HZ`, counting samples, not seconds: the take starts at `Audio::micSamples()` when Sing is pressed, reads only windows made entirely of later samples, ends after 3 s of them, and gives up with "no sound from the mic" if none arrive in 6 s (`startMic()` also clears the ring). Then `sungNote()` (median, nullopt under a third voiced) and `myVoice()` (at least a fifth, written in the preset's octave, the preset's techniques/instead/sound) do the maths. Save calls `saveInstrument()` and sets `Settings::instrument = "my-voice"`.

## Why
Owner's plan on #87: singers pick their own octave, other instruments keep "wrong octave"; the core does the maths and the GUI only records. Owner's review on #96: with the instrument-only search, the bottom eight or so notes of every voice sung an octave down were never detected, so folding never got a chance; on the web `getUserMedia` answers late and the ring held old audio, so a clock-timed take could read silence or stale sound. `my-voice` stores the English name "My voice" (the MCP server reads the file) and the GUI translates it through `instName()`'s `tr(in.name)`. A singer breathes whatever the sound, so `perform()` plays breath gaps when the player is a voice (the presets use the violin sound; there is no singing synth).

## How to apply
Test voice behaviour with rendered buffers and `judgeNote()`, never the mic: the `singing_voices` test in `tests/core/sound.cpp` renders vibrato takes framed like the GUI, a tenor's A3 through `Synth`, and each preset's lowest note an octave down (highest an octave up) through `micSearch()`: never compute the play-along window in the GUI. The main loop stays live while `a.audio.micOn()`, so a take gets a pitch for each new batch (the desktop loop otherwise waits for events). The small staff draws notes beyond three ledger lines above or four below an octave nearer with 8va/8vb (15ma/15mb). To snapshot the range window, patch locally: set `showRange`, `rangeFrom`, `rangeNote[]`, `rangeTake` with a negative `rangeMark` (the progress bar reads `micSamples() - rangeMark`, 0 with the mic off) and `rangeLast = 0`, then revert. A tooltip can be snapshotted by feeding `io.AddMousePosEvent()` after `ImGui_ImplGlfw_NewFrame()` in the patch. The lyric highlight follows `a.cursor` back over held/tied notes and bar lines to the syllable being sung; fake `a.cursor` after `practiceUpdate()` to snapshot it. The same-results test (#85) skips `voice-*` ids, and the catalog size asserts count them.
